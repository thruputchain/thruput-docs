# Groundhog Developer Docs

Developer documentation for the [Groundhog](https://groundhog.dev) L1 blockchain. Built with [Astro](https://astro.build) + [Starlight](https://starlight.astro.build).

## Development

```bash
pnpm install       # Install dependencies
pnpm dev           # Dev server at localhost:4321
pnpm build         # Production build to dist/
pnpm preview       # Preview production build locally
```

## Content

Markdown files live in `src/content/docs/`, organized by section. The sidebar is manually configured in `astro.config.mjs`.

| Section | Path | Description |
|---------|------|-------------|
| Concepts | `start/` | Background guides by developer archetype |
| Tutorials | `start/`, `tutorials/` | Getting Started + step-by-step contract builds |
| Tools | `tools/` | TypeScript SDK, block explorer, wallet, faucet |
| How It Works | `how-it-works/` | Architecture, execution model, contracts |
| Programming Model | `programming-model/` | Working model for contract authors: execution, storage types, NNInt, testing |
| Reference | `reference/` | Storage types, syscalls, SDK macros, error handling |
| Migration Guides | `migration/` | Stellar, EVM, Solana migration paths |
| Community | `community/` | Contributing, security, roadmap |

## Adding a Page

1. Create a `.md` file in the appropriate `src/content/docs/<section>/` directory
2. Add frontmatter with `title` and `description`
3. Add the slug to the sidebar array in `astro.config.mjs`
4. Run `pnpm build` to verify

## Agent guidance

The landing page points agents to `/start/build-with-an-agent/` for pre-install
access checks, then to the installed CLI's `groundhog --skill`. The hosted
reference is a pinned artifact, not an independently authored copy of CLI docs.

`public/agents/current.json` identifies the selected guide's CLI version, status,
SHA-256, and source. The initial reference is the **preview** generated by
`groundhog-rpc` commit `691a21f`; it has not been designated a hackathon release.
It remains subject to this site's existing early-access access controls.

To promote another guide:

1. Obtain `agent-guide.md` from the explicitly selected CLI release and verify it
   against that release's `SHA256SUMS`. Do not select the latest prerelease
   automatically. For a source preview, generate/check it at the recorded commit
   and compare it with that build's `groundhog --skill`.
2. Add those unchanged bytes at `public/agents/<cli-version>/agent-guide.md`.
   Retain earlier version paths. Never replace an existing version with different
   bytes; a corrected guide needs a new CLI release.
3. Copy the selected file to `public/agent-guide.md`, and update `current.json`
   with its version, `preview` or `release` status, source, and SHA-256.
4. Run `pnpm check:agent-guide`, `pnpm astro check`, and `pnpm build`.

The build checks that the current alias matches the versioned artifact, version
marker, and recorded checksum. Astro copies the Markdown unchanged. Deployment
uses the site's existing hosting process; building does not publish anything.

CI also compares versioned guide paths against the PR base commit (or the previous
commit for a push to main). Existing versions cannot be modified, removed, or
renamed, even if the alias and checksum are updated together. To run this check
locally, use `node scripts/check-agent-guide-history.mjs origin/main` after fetching
the base branch. Source-artifact verification in step 1 remains part of promotion.
