## Agreed structure

Guides contains an overview and six flat entries: Counter 1 (contract), Counter 2 (TypeScript), Counter 3 (React), Counter 4 (wallet), Build a token, and Build an AMM.

The counter parts create a scaffolded contract, a TypeScript client and development-signing server, a usable React counter, and a connected-wallet alternative. No clone is required. A supplied public Devnet checkpoint and a single binding download support app-only entry without Rust. The full example retains its worker, keyboard input, and concurrency controls.

Development signing is the default after provisioning. A successful wallet connection selects wallet signing. Only explicit disconnect returns to development signing. Rejection, unexpected session loss, and wrong-network state do not fall back. Submitted work keeps its original account, network, and hash for observation.

The token and AMM guides build and exercise the existing contract implementations with native and RV32 tests. The AMM guide explicitly scopes its result to the contract suite, not an unqualified browser deployment.

## Separate AMM RPC qualification

The existing `test:batching` live-node probe failed at pool creation against both managed runtimes 0.1.30-rc.1 and 0.1.29-rc.5 with CLI 0.22.1. Token creation and its expected rollback check passed. An isolated first pool step, native HOG `adjustAllowance`, also reverted; the root receipt reported DefaultWallet `CallAborted`. A view simulation returned an unknown exception selector `16529008398361299651` with payload bytes `01 00`. No root cause is claimed from this evidence alone.

The initial node-readiness parser also mixed stderr with stdout and mistook a structured huge-page warning for its JSON response. Separating stdout allowed the probe to reach execution. That diagnostic change and temporary per-call probes were lost with the temporary worktree; they are not changes to the original checkout.

This failure does not invalidate the passing native/RV32 contract scenarios. It does prevent claiming that the current browser/RPC AMM deployment has passed. Keep runtime-specific failure evidence internal and track qualification separately; do not add a reader-facing workaround to the guides.
