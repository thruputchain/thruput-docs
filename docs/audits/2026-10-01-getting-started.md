# Getting Started verification

Workstream: GH-447. Content issue: GH-451. Date: 2026-10-01.

## Agreed reader experience

- All four quickstarts target Devnet. A local node is not an onboarding prerequisite.
- Use current release installation commands without a reader-facing version matrix.
- Preserve dependency and compiler settings generated by the CLI, and npm lockfiles.
- CLI: create a wallet, request test funds, and inspect the transaction.
- Contract: create, build, test, deploy, initialize, increment, and read `15`.
- TypeScript: read native HOG total supply through a typed binding.
- React: display the same contract data, including pending/error states and Refresh.
- The application reads do not require Rust, a signer, or a deployment.

The user explicitly confirmed that Devnet updates should not delay writing the intended quickstarts. Network failures below are outstanding verification, not successful runs.

## Hosted-network follow-ups

The queried Devnet reported implementation `0.17.7`, packaging release `0.1.28-rc.6`, and wire format `5.2.0`.

1. **CLI funding:** `groundhog airdrop --profile devnet` returned `network_descriptor_mismatch`: expected faucet `schemaVersion` `4`, received `3`. Retest funding, transaction inspection, and contract deployment after the hosted update.
2. **Standalone TypeScript read:** the published client returned `Invalid view response: expected gasUsed to be a u64`. Retest the exact script after the hosted view response is updated.

The React consumer currently resolves a compatible older client through the library's peer requirement and completed its hosted read. This does not prove that the newer standalone client is compatible with the current hosted response.
